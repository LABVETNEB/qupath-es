# QuPath 0.7.0 - locale timing audit

How each bundle key behaves when the display locale changes **after** the
GUI has been built. Generated by `tools/locale_timing_audit.py` from the
class constant pools of the installed jars (read-only).

- Generated: `2026-09-02T15:51:41+00:00`
- Installation: `C:\Users\Nico\AppData\Local\QuPath-0.7.0\app`
- Bundle: `versions\0.7.0\base\qupath-gui-strings.properties` (894 keys)

## Classification method

A class is read as **locale-bound** if its constant pool references
`registerProperty`, `createProperty`, `LocalizedResourceManager` or one of
the `@ActionConfig` / `@ActionMenu` / `@Pref` annotations - all of which
route through `LocalizedResourceManager`, whose `refresh()` re-resolves every
registered property when the locale changes.

A class is read as **static** if it only calls
`QuPathResources.getString(...)`, which returns a `String` once and keeps no
link to the locale.

Each key is then classified by the classes whose constant pool contains it.

## Important caveat: static lookup is not the same as frozen at startup

`STATIC_AT_CONSTRUCTION` is an upper bound on the harm, not a count of
visibly wrong strings. Most of those keys belong to dialogs that are built
**when the user opens them**, so they resolve in whatever locale is current
at that moment - which, after the startup script has run, is Spanish.

## The genuinely affected set

Of the classes that only ever do a static lookup, these are the ones built
during application startup, so their text is fixed before the startup script
runs:

| Class | What it holds |
| --- | --- |
| `qupath/lib/gui/ToolBarComponent` | Toolbar tooltips |
| `qupath/lib/gui/viewer/tools/PathTools` | Drawing tool names |
| `qupath/lib/gui/viewer/ViewerManager` | Viewer placeholder text |
| `qupath/lib/gui/QuPathApp` | Startup messages |

Everything else on the start screen - the 13 menus, the action items, the
analysis-pane tabs, preferences, overlay and viewer actions - is
locale-bound and updates correctly. The end-to-end proof confirms this:
40 of 40 sampled keys resolve in Spanish.

## Relationship to the three strings that prompted this audit

`Image list`, `Search entry in project` and
`Drag & drop an image file or project folder` appear in **none** of the
categories above, because they are not bundle keys at all in 0.7.0: they are
string constants inside `ProjectBrowser.class` and `ViewerManager.class`.
They are unaffected by locale timing and cannot be translated externally.
See `pre-gui-locale-solution.md`.
